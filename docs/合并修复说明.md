## 追加修复：lazy='raise' 导致详情/发布 500

### 问题根因

PR#3 给 `Project.author` 关系设了 `lazy='raise'`（防意外 N+1，本身是好习惯），意味着访问 author 前必须显式预加载。

`detail_from_project`（详情组装，也被 create/publish 复用）里，"相关作品/其他作品/类似作品" 走 `cards_from_projects_with_stats`，但这些 related/other 项目**没有预加载 author**，一访问 `p.author` 就撞 `lazy='raise'` → 500。

实测：`GET /projects` 列表 = 200 ✅；`GET /projects/{id}` 详情 = 500 ❌；`POST /projects` 发布 = 500 ❌。

### 修复方案（选 A）

让 `cards_from_projects_with_stats` 自己批量加载 author，不依赖关系预加载：

1. 收集入参项目的 `author_user_id`
2. 一条 `select(User).where(User.id.in_(author_ids))` 拿回
3. 组成 `{user_id: User}` 再分发到各卡
4. **不访问 `p.author` 关系**（那个被 lazy='raise' 挡住）

这样无论调用方有没有 selectinload，函数都自洽，不会再撞 lazy='raise'。

**代码位置**: `app/services/projects.py` Line 327-352

```python
# 批量查询 author（不依赖 lazy='raise' 的关系，自己查 user 表）
author_ids = [p.author_user_id for p in projects if p.author_user_id is not None]
author_map: dict[uuid.UUID, User] = {}
if author_ids:
    authors = db.scalars(select(User).where(User.id.in_(author_ids))).all()
    author_map = {u.id: u for u in authors}

for p in projects:
    # 从批量查询结果取 author，不访问 p.author 关系（避免 lazy='raise' 报错）
    author = None
    if p.author_user_id and p.author_user_id in author_map:
        author = user_brief_from_user(author_map[p.author_user_id])
```
