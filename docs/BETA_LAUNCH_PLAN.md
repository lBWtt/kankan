# 看看 Android 内测上线与首批用户验证规格

版本：1.0  
日期：2026-08-13  
当前运营主体：成都市环球远景贸易有限公司（正式发布前必须与营业执照逐字核对）

## 1. 这轮要回答的问题

这轮不是验证“能不能把 App 做出来”，而是用真实陌生用户回答四个问题：

1. 用户看到一句话和代表作品后，是否愿意进一步了解？
2. Android 用户是否愿意跨过下载、安装门槛？
3. 安装后是否会主动浏览多个作品并点击“去体验”？
4. 第二天是否还有理由回来？

任何新增功能都必须直接帮助回答以上问题，否则不进入本轮。

## 2. 定位与对外表达

产品名：看看  
一句话定位：每天帮你筛出真正做出来、值得体验的个人作品。  
补充说明：不是 AI 新闻，也不是大公司 App 广告；先看成果，再决定要不要亲自体验。

首批目标用户：

- 对 AI 新产品、vibe coding、独立开发感兴趣的人；
- 经常在小红书、抖音、即刻看到演示，但找不到真实体验入口的人；
- 想获得产品灵感或寻找可直接使用小工具的人。

暂不承诺：iOS 客户端、全平台覆盖、作品数量最多、所有体验入口都可用。

## 3. 用户链路

```text
小红书内容/朋友转发
  -> 移动承接页
  -> 看懂定位并浏览代表作品
  -> Android 下载
  -> 安装并首次打开
  -> 浏览卡片/打开详情
  -> 点击作品真实体验入口
  -> 次日再次打开或提交反馈
```

网页是承接页，不是流量来源。第一轮流量主要来自小红书内容、定向邀请和朋友转发。

## 4. 本次交付边界

本次只实现网页承接与网页获客验证，不修改手机 App 代码，包括但不限于 Flutter 页面、Android 包名、签名、版本、App 埋点和手机端法律文本。

现有 APK 作为网页下载对象原样使用。以下 Android 身份事项只作为未来公开分发前的待办，不在本次实施。

### 5.3 最小数据闭环（本次只实施网页事件）

网页事件：

- `landing_view`：打开承接页；
- `landing_project_click`：点击代表作品；
- `android_download_click`：点击下载；
- `ios_interest_click`：iPhone 用户表达兴趣；
- `landing_feedback_click`：点击反馈。

App 核心事件沿用现状，本次不改代码：

- `app_open`；
- `card_impression`；
- `card_click`；
- `detail_view`；
- `try_click`。

每个网页事件必须携带匿名访客 ID、来源参数 `utm_source/utm_campaign/utm_content`、平台和页面版本。App 平台字段修正留作未来待办，本次不修改。

运营账号数据不计入真实用户核心口径；后台仍可单独显示管理员活动用于排障。

## 6. 7 天小红书实验

不是一次发完，而是用 3 个内容角度各测试 2 篇：

1. 筛选价值：“我翻了 300 个作品，留下这 9 个真能玩的”；
2. 作品冲击：“原来一个人已经能做出这些东西了”；
3. 建造故事：“花两个月做了个 App，专门找藏在短视频里的真实作品”。

每篇要求：

- 第一张图必须是最强作品成果，不用纯 Logo；
- 前三行先交付发现，不先介绍自己；
- 展示 3～7 个真实作品；
- 结尾只放一个行动：去主页承接页体验 Android 内测；
- 链接分别使用 `utm_content` 标记，不能六篇共用无法区分的链接。

建议链接示例：

`https://lovluu.com/?utm_source=xiaohongshu&utm_campaign=beta01&utm_content=filter_a`

## 7. 决策指标

第一轮目标不是规模，而是信号质量。7 天后按漏斗判断：

| 层级 | 指标 | 初步通过信号 |
|---|---|---|
| 内容 | 小红书主页访问/私信/评论询问 | 至少有陌生人主动问如何体验 |
| 承接 | 下载点击 / 独立访客 | 有稳定点击，不要求大样本百分比 |
| 激活 | 首次打开 / 下载点击 | 能识别明显安装流失并收集原因 |
| 使用 | 详情打开用户 / 首次打开用户 | 多数真实测试者至少打开 3 个详情 |
| 价值 | 去体验点击用户 / 详情用户 | 至少 3 个真实用户发生去体验点击 |
| 留存 | 次日再次打开 | 至少 3 个真实用户回来或主动反馈 |

样本不足时不使用漂亮百分比下结论，先看逐个真实用户的行为路径和原话。

## 8. 决策规则

- 曝光不足：调整内容选题与封面，不改 App。
- 有访问、无下载：降低安装与信任门槛，补网页可浏览内容，不盲目加 App 功能。
- 有下载、无首次打开：排查签名、安装拦截、兼容性和下载包可信度。
- 有打开、无详情：首屏内容或编排失败，回到内容宪法与 slate。
- 有详情、无去体验：项目不够可体验或体验入口质量不足。
- 有体验、无回访：需要稳定更新节奏、收藏/提醒价值或更明确的使用场景。
