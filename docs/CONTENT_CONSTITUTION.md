## 〇、背景（这个产品是什么、给谁）
kankan = 面向**数字游民与创作者**的「AI 作品**发现 + 展示 + 直接给人用**」社区。创作者把自己做的网站/app/AI 作品发上来，别人来**看、用、体验**——本质是**作品集 + 自我推销**，商业方向面向数字游民。**明确不是**教程 / 复现 / 「想看怎么做」。本宪法管的是"**发现并收录别人的作品**"这条内容线的最高准则（另有"用户自己发布"线不在此文）。

## 一、使命
kankan 发现普通个体做出的完整作品，让用户**五秒看懂它哪里厉害**，并能观看/体验/复用。「理解创作者巧思」放详情页，不要求首屏承担。
> 注：**真实作者归属（联系原作者/署名）= 未来阶段**——原作者难联系，现在维持现状（发布仍用站内策展作者），不为它拖慢"做出吸引人内容"。

## 一·补 · 冷启动最高规则
内容**首先必须吸引人**。「是不是作品」决定能否入库；「五秒内是否让人想继续看」决定能否发布和进首屏。**宁缺毋滥：每天发 5～8 条强内容，绝不用普通内容凑数。**

---

## 二、第一道闸（入库）：作品 vs 原料
判断轴是**作品 vs 原料**，不是"个人 vs 公司"（公司做的好作品也能过这道闸，后面用配比控制其占比）。
- ✅ **作品**：app、网站、**工作流**、有具体用途的**模型**、**提示词**、AI 生成作品、创意实验、小游戏、小工具。**不限形式**。
- ❌ **原料**：通用库、框架、SDK、引擎、数据集、协议、命令行脚手架。
- 灰区：编程语言/通用底座 → 原料，拒；个人 fine-tune 的「专门做 XX」模型 → 作品，收。

不是作品 → 不入库。

## 三、第二道闸（发布 + 首屏）：吸引力闸门
每条作品，模型输出以下五项分项（各 0～100），**后端自己算总分**（模型不做算术）：

| 字段 | 权重 | 判断 |
|---|---:|---|
| `hook_clarity` | 25% | 只看封面和标题，五秒内能否明白效果 |
| `visual_impact` | 25% | 是否有成果图、前后对比、演示视频 |
| `surprise` | 20% | 是否产生"居然还能这样"的感觉 |
| `tryability` | 15% | 能否立即观看、试玩、使用或复用 |
| `shareability` | 15% | 是否值得转给朋友或发群里 |

```text
attraction_score = hook_clarity×0.25 + visual_impact×0.25 + surprise×0.20 + tryability×0.15 + shareability×0.15
```

另出 **`value_score`（0～100，实用价值）**：只用于同吸引力档内排序 + 第七章"≥3 条实用价值"的判定（`value_score ≥ 70` 记为有实用价值）。**value 不参与 attraction，不单独决定首屏。**

执行标准：
- `< 60`：直接淘汰；
- `60～69`：留候选池，不发布；
- `70～81`：可发布；**进首屏受第七章名额限制**（不是无脑进）；
- `≥ 82`：首屏强候选；
- **`hook_clarity < 60`：无论总分多少都不进首屏**；
- **没有成果证据图或演示视频（proof_media）：原则上不发布。**

**证据校准（正式项目选取规则）**：
- **[全平台]** 文本模型只看到文案/媒体 URL、没有实际检查成果图或演示关键帧时，`visual_impact` 状态记为未核验，**最高 70**；只有截图、关键帧或演示画面经视觉模型/人工实际检查后才能突破。程序自动抽帧只增加待选证据，不等于已经完成视觉核验。
- **[全平台]** `experience` 三件套没有形成真实可达体验时，`tryability` **最高 50**。有效的 `prompt_content` 正文、`workflow_file` 内容同样算真实体验，不强求 URL；帖子页、视频页、仓库 README 不算。
- **[全平台]** 已判定为完整作品、但缺真实体验入口的优秀候选，不因缺链接直接删除；限分后仍达候选标准的，停在“AI已整理”等人工寻找作品真链接。人工补链后重新走发布闸。
- 模型原始分必须保留，限分后的当前分另存，并记录命中的校准规则，允许人工核验后恢复。
- **[全平台原则、平台内校准]** 点赞、收藏、分享可校准 `shareability` 与召回优先级，但**不能把教程/观点救成作品，也不能替代视觉核验或体验入口**；不同平台必须分别校准互动阈值。
- **[仅抖音]** 作品发布超过 14 天且点赞低于 100，未经人工确认不得评为 `≥82`（确定性压到最高 81）。该数字不外推到其它平台。
- **[仅抖音]** 当前发现队列按 `点赞 + 2×收藏` 排有限 DeepSeek 预算；这是抖音内部顺序，不与其它平台横比，也不直接加 attraction 总分。

## 四、每条内容必须交付这五样（不满足不发布）
```text
1. hook_title        ：结果导向标题（模型出 2 个候选，见第五章）
2. proof_media       ：证明效果的图片或视频（见第六章）
3. hook_sentence     ：一句话说明为什么值得看
4. experience 三件套 ：见下（不再强求是 URL）
5. creator_name      ：作品创作者名（现阶段可为站内策展作者，未来接真实作者）
```
**体验入口拆成三件套**（这样提示词/工作流/模型页不会因没独立网站被误杀）：
```text
experience_type    ：web | video | gallery | download | model_page | workflow_file | prompt_content | game
experience_url     ：可空（web/video/model_page/game 等有链接时填）
experience_content ：可空（prompt_content 存提示词正文、workflow_file 存工作流等无独立 URL 的内容）
```
后端发布闸**不再强制 http/https**——按 `experience_type` 校验：有 url 类型校验 url，content 类型校验 content 非空。

**铁律：体验入口 = 作品本身，不是我们的源。** 用户点「去体验」是去玩/用/看那个作品，**绝不能落回采集源页**——禁止把 `experience_url` 填成 Reddit 讨论帖 / PH 的 listing / 抖音小红书视频页 / itch·HuggingFace 的搜索列表页 / GitHub 的 repo 首页。必须落到"作品的家"（能直接玩/用/下载/观看的那一页）。各源如何解析到作品本身见第九章。

## 五、标题硬规则
12～28 汉字；**先说结果，再说工具**；不以项目名/模型名/技术名开头；禁「基于…打造」「一个…工具」「开源项目推荐」；必含具体效果/反差/场景。

| 原标题 | 改成 |
|---|---|
| 基于 ComfyUI 的角色一致性工作流 | 只画一次角色，换十个场景也不会变脸 |
| 开源 AI 音乐生成模型 | 哼两句旋律，它能补成一首完整歌曲 |
| 一款 AI 简历优化工具 | 把招聘要求贴进去，简历会逐条帮你改 |
| GitHub 上的开源数字人工具 | 一台普通电脑，也能跑自己的实时数字人 |
| AI Prompt 工作流分享 | 这段提示词能把流水账变成可拍的视频脚本 |

**模型必须同时输出两个标题候选（`title_candidates`），审核员选更抓人的一个。**

## 六、封面硬规则
优先：① 最终作品效果 → ② 前后对比 → ③ 使用过程关键一帧 → ④ 6～20 秒演示视频/动图 → ⑤ 产品界面。
**禁止作为首图**：Logo、GitHub 社交卡、仓库首页、纯文字海报、模糊截图、与结果无关的作者照片、普通官网首页截图。
每条候选至少备 2 张效果图，审核选最容易看懂的一张（`selected_proof_media`）。
采到图片/视频 URL 只代表“有媒体”，不代表已经验证画面内容。视觉核验状态至少区分 `unverified / frame_checked / demo_checked / human_checked`；`unverified` 受第三章 `visual_impact ≤70` 约束。

## 六·补 · 简介/正文文案（summary / description）
标题之外的正文也要有网感、不模板腔：
- **禁定义句开头**：不许以「X 是一个/一款/一种/一套…」起（最大的模板腔来源；代码有 `_strip_definition_open` 兜底）。
- **按写作角度切入**：不同项目用不同角度（亮点先行/场景切入/冷静测评/发现感/反差…），读起来像不同的人写的，不是统一说明书腔。
- **禁提来源与原作者**：不许出现「作者/开发者/博主/一位用户/有人做了/据原帖/抖音·小红书·GitHub 上…」——只介绍"这个作品本身"，让用户留在站内。也别用「我做了/我试了」冒充。
- 有守护测试 `tests/test_content_style.py`，改坏会红。

## 七、首页首批十条（slate 编排，后端做，不在前端排）
生成首页 slate（前十条）必须满足：
- 至少 6 条 `attraction_score ≥ 82`；
- **70～81 的最多占 4 条，且只为补足形式/题材多样性**；
- 至少 4 条能直接玩/试/观看（`is_direct_tryable`）；
- 至少 3 条有实用价值（`value_score ≥ 70`）；
- 至少 2 条强视觉（`is_strong_visual`）；
- 同一平台最多 2 条；同一作品形式最多 2 条；
- GitHub / 模型 / 工作流不能连续出现；
- 公司产品最多 1 条；
- **第一条必须 `attraction_score ≥ 82` 且 hook_clarity、visual_impact 都达标（≥ 80）**。

参考编排：`1 最强视觉钩子 2 马上能玩 3 实用且效果明确 4 意外/猎奇 5 马上能玩 6 强视觉 7 实用 8 个体反差 9 马上能玩 10 当天最独特`。

**架构**：后端建「slate 编排器」——合格池过滤 → 按 attraction/value 排序 → 贪心+修复满足上述配额 → 生成带版本的十条 slate → 人工预览 → 前端按位置原样展示。**库存不足时宁可返回少于十条，并记录缺哪项约束**，绝不放松质量门槛/证据媒体/公司上限。随机只用于同档平局打散，不再主导排序。

## 八、配比（两维，别用单桶；按最近 100 条已发布滚动统计）
拆成两个正交维度，各自卡上限：
```text
creator_type   : indie | company        → company ≤ 5
access_friction: instant | install | technical → technical ≤ 15
其余（indie + instant/install）= 主菜，占大头
```
判定：个人/小团队作品（哪怕收费）= indie；公司团队/融资/品牌营销 = company；点开即用 = instant，要装但是成品 = install，要技术/命令行/搭环境才能用 = technical。**GitHub 只是来源，不决定这两个维度。**

**公司广告闸（2026-08-12 补充）**：公司身份本身不自动判死，但公司/品牌产品发布稿、成熟 SaaS/App 的获客宣传、营销落地页不得作为“个体做出来的成果”入选。正文若以客户触达、销售跟进、广告投放、转化率、获客成本、企业效率等品牌卖点为主，或只是标准产品功能宣传，即使有真实官网、可体验、票数高、maker 人数少，也判原料/广告（`is_work=false` + `suspected_ad`）。只有能证明是个人/小团队的具体创作过程与成果展示，而非品牌获客稿，才按 indie 作品评审。
**company 达 5 条后，后续 company 即使高分也暂停发布**，直到滚动窗口释放名额；technical 同理卡 15。

## 九、源策略与冷启动配额

### 9.0 搜索/查询原则（关键，约束所有关键词类采集器）
**按「个体用 AI 做出来的成果 / vibecoding 作品」去搜，不是按「AI」这个话题词去搜。**
- ❌ 别用泛词：`AI`、`人工智能`、`AIGC`、`大模型`——只会捞回资讯、公司产品、工具评测、教程洪水。
- ✅ 用**"展示自己做的东西"的意图词 + 作品类型**：
  - 意图/成果：`我用AI做了`、`vibe coding`、`一个人做了`、`独立开发`、`做了个小工具/网站/小游戏`、`AI生成了`、`用AI搓了个`、`周末做了`、`side project`、`I built`、`made with AI`、`show hn`。
  - 形式限定：小工具 / 网页 / 小游戏 / 工作流 / 模型 / 提示词 / 创意实验。
- 原则一句话：**搜"作品和创作行为"，不搜"AI 话题"**；捞回来的应是"某人做出来的一个东西"，不是"关于 AI 的一条内容"。
- 各源落地：小红书/抖音/即刻/X/Reddit 的搜索词、GitHub 主题、PH/HN 的过滤，都照此设关键词（别只放 `AI`）。

### 9.1 配额
每天：`采 50～80 → AI 初筛留 15～20 → 人工看封面标题留 8～12 → 发 5～8`。
来源优先级（冷启动）：① 小红书/抖音**高赞高收藏**（无链接→人工加体验入口）② Reddit InternetIsBeautiful/somethingimade ③ itch.io 可玩创意 ④ HuggingFace/魔搭有明显效果演示的 Space ⑤ PH 个人+视觉强 ⑥ GitHub 只收有真实演示+成果截图的个人作品。GitHubDaily/HelloGitHub 只作补充发现源。其它个体源（即刻/少数派/V2EX/Devpost/Civitai/OpenArt/LiblibAI/X）按同标准逐个接入。
互动只在平台内比较：抖音当前发现队列用“点赞 + 2×收藏”安排有限 AI 预算的处理顺序（收藏意图权重更高），不拿该公式横比 HuggingFace、Reddit、GitHub 等平台。

### 9.2 各源如何解析到「作品本身」（落实第四章铁律）
- Reddit / 即刻 / V2EX / Devpost：取帖子里作者贴的**真实作品外链**，不是帖子本身。
- Product Hunt：跟 `/r/` 跳转解析到**产品真官网**，不是 PH 页。
- 小红书/即刻：只要有明确的个体成果语义和帖子内成果图/演示，可在暂缺真实作品链接时先进入 `ai_processed`，标记待人工补体验入口；proof 仍是硬闸。缺链接时 `tryability≤50`，不得自动发布，审核员补到真实入口并核验后再发布。
- itch.io：该游戏的**可玩/可下载页**（itch 上玩=去体验，OK；但要具体作品页，不是分类/搜索页）。
- HuggingFace / 魔搭：个人 **Space 可玩 demo** 或**模型页**，不是站点首页。
- Civitai / OpenArt / Tensor.art / LiblibAI：该**工作流/模型的具体页**（可下载/可用）。
- GitHub：个人作品的 **hosted demo / 官网 / 直接 release 安装资产**（repo/README 链接已被发布闸拦）。抖音、小红书或策展文章即使只是展示 GitHub 项目，也可作为发现线索；原项目面向大众且能追到网页版、Windows/macOS 安装包或其它直接可用入口即可收，同一体验入口仍只留一张卡。
- 小红书 / 抖音：平台不给链接 → **人工补作品真链接**（审核台「加链接」），不是视频页。

### 9.3 采集执行
- **别一次接十几个源，分两批**：第一批（免登录/可达，先出多源货）Reddit(InternetIsBeautiful/somethingimade/SideProject)、itch.io、HuggingFace/魔搭、LiblibAI、PH(GraphQL)、少数派；第二批 即刻(Playwright)、Devpost、Civitai/OpenArt、X(CDP)、小红书/抖音(人工加链接)。
- **国际源从本机采**（走 Clash `HTTPS_PROXY=http://127.0.0.1:7897`），国内源直连；产出标准 item → `docker cp` 进容器 → `python -m app.pipeline collect … --platform X` + `process`（v1.1，max_tokens≥8000，可用 1M 上下文塞本宪法+校准示例）。
- **proof 采集时就要抓到效果图**（源页里的成果截图/演示帧），补不到宁可不收。
- 生产机 `ubuntu@118.89.112.187`（腾讯云上海）；旧 IP `47.109.198.37` 已停/回收，**永不连**。机场（服务器代理）留到"上量"阶段再配，第一批本机采即可。

## 十、上线后指标（= 测量阶段，phase 2；现在先把内容做吸引人，别先堆埋点）
每条累计 **200 个独立有效曝光**（且跨≥1 天）后判断四数字：
```text
有效曝光    ：卡片 ≥50% 可见并持续 ≥1 秒
首屏停留率  ：有效曝光中，持续可见 ≥5 秒的独立会话比例
详情点击率  ：独立详情点击 / 独立有效曝光
体验点击率  ：确认打开体验入口 / 独立详情访问
收藏+分享率 ：发生收藏或完成分享的独立会话 / 独立有效曝光
```
埋点需带 `slate_id / position / surface / feed_session_id` 才能排除位置差异。淘汰/加码：停留后 30% 移出首屏；体验点击 <3% 查标题按钮；收藏分享 <2% 停采同类；前 20% 继续采同来源/效果/标题结构。前两周不做复杂推荐，每天复盘最好 5 条+最差 5 条。
