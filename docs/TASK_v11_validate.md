# 任务书（给 codex）：验证 v1.1 筛选是否真的筛出有价值内容

> 目标：**先验证，再决定要不要继续 rollout**。用最小动作让 v1.1 的筛选结果直接显示在审核台，用户一眼判断"筛出来的是不是真有价值"。**如果筛出来的没价值/为空，就停在这里，别做后面的部署上线/采集器/机场。**

## 背景
- v1.1「先做」代码已完成（评分五维、is_work 闸、experience 三件套、proof 媒体、发布/首屏闸、slate 编排器），但**尚未部署、未迁移、未提交**，线上仍是旧版。
- 现有候选/项目是**旧标准**下、且多为"搜 AI 泛词"采回来的，本次只用它们**验证 v1.1 的评分与闸门**是否把有价值的挑出来、把水货压下去。搜索原则（宪法 9.0）留待后面采集器阶段做，不影响本次验证。

## 具体行为
1. **提交一个 checkpoint**（当前工作树的 v1.1 改动），便于回退。
2. **部署 v1.1 到生产**：跑 alembic `0023` 迁移 + 重建 backend 容器（前端本次不必重打，验证只看审核台）。确认容器起来、`/health`、OpenAPI 正常。
3. **用 v1.1 AI 重新处理一批现有候选**（pending_review / ai_processed / 部分老项目对应候选，限 30～50 条）：
   - 走新 `ai_processor`（五维分、is_work、work_form、creator_type、access_friction、双标题、experience 三件套、value_score、selected_proof_media）。
   - 注意 DeepSeek v4-flash 是推理模型，`max_tokens≥8000`（已修）。可用 1M 上下文把宪法+校准示例塞进 system。
4. **产出一份验证快照**（给用户看，别只报数字）：
   - 处理 N 条：`is_work=False 拦下 X` / `进 pending_review Y` / `attraction<70 压下 Z` / `失败 F`；
   - 列出**进入审核台的前 10 条**：标题（双候选取一）、attraction_score、value_score、work_form、creator_type、有没有 proof 媒体；
   - 列出**被拦下的代表 5 条**：标题 + 拦下原因（原料 / 无 proof / 低吸引力）。
5. 让用户**打开审核台**（lovluu.com/admin-web，队列按分排序）**直接看**这些卡片是不是"有价值、想点开"。

## 验收/决策
- ✅ 若审核台里能看到**一批明显更抓人、更像"个体作品"的卡片**（哪怕只有个位数），且水货被有效拦下 → 验证通过，回来告诉用户，再谈后续（内容 bootstrap 20-30 条 / 机场 / 采集器）。
- ❌ 若筛出来的仍是水货、或几乎全被拦成空、或评分明显不合理 → **停**，把问题样本贴出来，我们回头调宪法/prompt，**不做后面任何 rollout**。

## 约束
- 别碰真实作者/马甲逻辑（未来阶段）。
- 别急着上采集器/机场/埋点（Phase 2）。
- 本任务只为"看 v1.1 筛得准不准"，最小改动、可回退。
