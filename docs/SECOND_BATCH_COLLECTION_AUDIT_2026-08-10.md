### 第二轮普适性验证约定（仍不写入宪法）

- 将新规则拆开验证：`visual_impact` 未核验限分与缺真实入口时的 `tryability` 限分按跨平台规则观察；“14 天/100 赞”仅是抖音实验；点赞收藏的绝对阈值和排序权重必须按平台单独校准，暂不视为普适规则。
- 抖音里展示 GitHub 项目效果的内容不因“搬运自 GitHub”直接淘汰：若原项目面向大众，并能追到可直接使用的网页版、Windows/macOS 安装包或 release 资产，可以作为作品发现线索；GitHub 仓库/README 仍只算代码出处，不能冒充体验入口。
- 第二轮采用抖音新样本 + 非抖音真实体验样本的对照批；只有两组都减少虚高且没有系统性错杀，才考虑把证据限分原则升级进宪法。

### 第二轮结果与固化结论

- 实际新增 7 条：抖音 3、HuggingFace Space 3、从 GitHub 追到独立官网的 NightRun 1；另有 4 条魔搭结果因真实体验入口与库存重复自动跳过。
- 抖音：建筑照片转极简海报原始五维合成约 `82`，因视觉未核验且缺体验入口校准为 `74/74`；10 分钟网页作品 `71/78`；只播报“App 15 万用户”但不展示功能的内容 `35/35` 淘汰。
- 非抖音：NightRun 从 GitHub 仓库追到 `https://nightrun.io`，有真实安装说明，校准后 `79/70` 并进入待审核；三个 HuggingFace Space 均保留真实入口与 `tryability=90`，但视觉/钩子弱时仍只有 `42/55`、`64/60`、`57/75`，没有被“可体验”单项抬成强候选。
- 结论：视觉未核验 `≤70`、体验三件套不成立时 `tryability≤50`、原始分与校准分并存三项在社交源与直接体验源都减少虚高，升级为跨平台宪法规则；“14 天/100 赞”和“点赞+2×收藏”只固化为抖音专项，不外推其它平台。
